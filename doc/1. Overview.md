# 1. Overview

This is an exploration of control strategies for Home Energy Management Systems (HEMS).

We simulate a set of 250 virtual households to compare different control strategies.

This involves future-agnostic, rule-based controllers as baselines as well as controllers that rely on predictive machine learning and mathematical models (MPC).

Both MPC and predictive ML are examples of systems implying their own logic so engineers dont have to come
up with all them rules themselves.

Even without user-specific knowledge, we can use ML technologies to greatly improve our decision making.

## Setup and Usage

### Quickstart

Create and activate a virtual environment, then install dependencies from the
repository root:

**Linux / macOS**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

**Windows PowerShell**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Run households 1-20 for both `default_scenario` and `00_baseline`:

```bash
python -m src.simulation.simulation \
  --households 1-24 \
  --scenarios default_scenario,00_baseline \
  --controllers waterfall,mpc_history_avg,mpc_oracle,mpc_single_step,mpc_multi_step,mpc_multi_model
  --run-id demo
```

### General usage

Run a simulation batch from the repository root:

```bash
python -m src.simulation.simulation \
  --households <selection> \
  --controllers <controller-list> \
  --scenarios <scenario-list> \
  [other options]
```

Comma-separate multiple controllers and scenarios. Household selections can
combine IDs and inclusive ranges, for example `1-20,25`.

- `--households`: household IDs/ranges, or `all` to run all households.
- `--controllers`: `no_control`, `fast_charge`, `even_linear`,
  `price_aware_linear`, `waterfall`, `mpc_oracle`, `mpc_history_avg`,
  `mpc_single_step`, `mpc_multi_step`, `mpc_multi_step_recursive`,
  `mpc_multi_model`, `mpc_multi_model_recursive`,
  `mpc_multi_step_high_res`, or `mpc_multi_model_high_res`. `all` selects the
  default controller set; the two high-resolution controllers must be named
  explicitly.
- `--scenarios`: `00_baseline`, `01_relaxed_flexible`,
  `02_default_benchmark`, `02a_wide_soc_range`, `02b_tight_soc_range`,
  `12_even_ramp_up`, or `22_early_stress`. `default_scenario` is an alias for
  `02_default_benchmark`; `all` selects every registered scenario.
- `--max-households N`: limit the selected households to the first `N`.
- `--start-time N`: start at period 1-96 (default: 1).
- `--run-id ID`: set a specific ID for this simulation batch.
- `--parallel-workers N`: number of worker processes (default: 6).
- `--parallel-households`: run households in parallel; this is enabled by
  default.
- `--help`: show command-line help.

Example:

```bash
python -m src.simulation.simulation \
  --households 1-20 \
  --controllers waterfall,mpc_history_avg,mpc_oracle \
  --scenarios 00_baseline,default_scenario \
  --run-id comparison-1
```

## Inspect results

Install the requirements if you have not already, activate the virtual
environment, then start the Streamlit dashboard from the repository root:

**Linux / macOS**

```bash
source .venv/bin/activate
streamlit run src/dashboard/dashboard.py
```

**Windows PowerShell**

```powershell
.\.venv\Scripts\Activate.ps1
streamlit run src/dashboard/dashboard.py
```

Open the local URL printed in the terminal (usually `http://localhost:8501`).
Alternatively, on Linux/macOS run `./run_dashboard.sh`, or on Windows run
`.\run_dashboard.ps1`.

The dashboard includes:

- **General Performance:** compare aggregate time-series profiles across runs,
  scenarios, metrics (cost, load, total cost, or total consumption), and
  selected controllers.
- **Single View:** inspect one household's results for a selected run and
  scenario. Compare controllers across load, PV, BESS, EV, net-load plots, KPIs,
  and debug details.
- **Prediction Explorer:** inspect actual source profiles and controller
  predictions for an individual household. Select the predictor/model family
  and profile to compare forecasts with the source data; this view is available
  even before simulation results exist.
