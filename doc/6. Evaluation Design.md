# 6. Evaluation Design

Each simulation run covers one household, one scenario, and one controller. A batch combines these runs to compare controllers on the same households and scenarios.

- **Charging targets.** For each scheduled state-of-charge (SOC) target, a controller must meet it in at least 95% of applicable runs to qualify for cost comparison. Report target attainment rates over all applicable runs.
- **Net electricity cost.** Calculate the daily cost of grid imports and workplace charging, minus revenue from grid exports. For each pair of qualifying controllers, compare costs only on matched household–scenario runs in which both controllers meet all applicable targets. Report the number of matched runs. The baseline scenario has no charging targets, so all matched runs enter its cost comparison.
- **Forecast accuracy.** Report RMSE separately for each predicted variable. Use one-step RMSE to assess the immediate forecast, overall RMSE across valid forecast–observation pairs, and a two-dimensional view indexed by forecast start period and lead time to show where errors occur.

## 6.1 Scenarios

The scenarios vary initial SOC, the permitted SOC range, and the EV charging targets. Periods 70 and 96 refer to the simulation's 15-minute periods. LOW, MID, HIGH, and DEFAULT retain their definitions from the scenario configuration.

| Scenario | Initial SOC | Allowed SOC range | EV target at period 70 | EV target at period 96 |
|---|---:|---|---|---|
| `00_baseline` | 50% | DEFAULT | — | — |
| `01_relaxed_flexible` | LOW | DEFAULT | LOW | MID |
| `02_default_benchmark` | LOW | DEFAULT | LOW | HIGH |
| `02a_wide_soc_range` | LOW | 5–95% | LOW | HIGH |
| `02b_tight_soc_range` | LOW | 30–70% | LOW | HIGH |
| `12_even_ramp_up` | LOW | DEFAULT | MID | HIGH |
| `22_early_stress` | LOW | DEFAULT | HIGH | HIGH |

## 6.2 Controllers

The evaluation compares Waterfall with five MPC variants using different forecasts:

- **Waterfall** uses fixed rules.
- **Oracle MPC** uses the actual future inputs as a reference.
- **Historical-average MPC** uses a simple forecast as the baseline for learned forecasts.
- **XGBoost MPC** uses recursive single-step, shared-model multi-step, or separate-model multi-step forecasts.
