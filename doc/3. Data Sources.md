## 3. Data acquisition and preparation

The original dataset is stored in a SQLite database and combined with external profiles for load, PV, and EVs.

## 3.1 Original dataset and database structure

### Origin

We mostly rely on the dataset from [this paper](https://www.sciencedirect.com/science/article/pii/S2352340923003372?via%3Dihub) from june 2023.

Everything is stored in an [Excel workbook](data/dataset_original/EC_EV_dataset.xlsx). Table Descriptions can be found in [the General Description](/data/dataset_original/General%20description.docx)

`src/ingestion/table_loading_original.py` reads the relevant 
Excel ranges and writes the source tables to
`sqlite/source_original.db`.

The original database is then copied as `sqlite/source_runtime.db`, where profiles for base load, PV and EVs are replaced with new consumer data.

### Format

The original Excel file contains technical lookup-tables as well as 96-step time series data.

Time series are stored as wide tables, with one `period` column (1-96) and columns `"1"` through `"250"` for the day profiles of each household.

## 3.2 Inserting foreign data

We replace the original load, PV, and EV profiles with more diverse real-world data.

## 3.2.1. Load Data

### Source

For load profiles,we use this residential dataset from Switzerland: https://zenodo.org/records/21398769?preview_file=dataset.zip

[See paper](/data/dataset_CH_load/descr_paper.pdf)

### Filtering

The consumption data is stored as a set of CSV files, one per household ID.

We keep households with installation type `'Single-family house'` that have at least 70.000 data points, where all of these metadata flags are false:
`1_ewh`, `1_hp`, `1_hp-add`, `1_hp-wh`, `1_ev`, `1_storage_heating`,
`1_direct_heating`, and `1_change`.

The column `kWh_to_installation` is multiplied by 4 to convert the energy to average power in kW for the 15-minute intervals.

These values are then used to create a wide `load` table in `sqlite/staging/CH_loads.db`.

Day profiles are valid for runtime and training pools if the total energy as well as the peak load are within the ranges of the original profiles.

Days with any missing datapoints are filtered out.

The selection of the 250 replacement load profiles aims to not change the contractual power level (CP) of the consumers from the original dataset, in order to preserve the balance of the simulation energy flows.
So for each household we determine the allowed range for its peak load, based on the table `General Information -> Contractual Power Term` in the [EC_EV_dataset.xlsx](/data/dataset_original/EC_EV_dataset.xlsx).

40 of the 81 CH load households with valid peak loads are then used to replace the original profiles.
The selection is spread out so that per household, 6 or 7 end up in the simulation data.

No further scaling is applied.

A set of 1000 load-days is randomly selected from the remaining household IDs to be used in model training.
